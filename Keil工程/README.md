# 第16队 STM32F103C8T6 自动行驶小车 Keil5 工程

> 固件标识：`Q2-GRAY-UART r8`（上电串口第一行会打印这个字符串）
>
> 本版把 **Q2 的弧线**改成"串口八路灰度循迹"：
> 灰度模块不再接 8 根 OUT 线，而是用 **UART 115200** 读原始 8 路灰度；
> Q2 的直线和两个 180° 弧线全部由灰度闭环跟线，IMU 只做航向环的内环和
> 里程/角度保护。Q1、Q3、Q4 的控制逻辑没有改动。

---

## 0. 本版改了什么（与 release1.9 的差别）

| 项目 | release1.9 | 本版 r8 |
|---|---|---|
| 灰度读数 | 8 根 OUT 并口 → GPIO | **UART 串口协议**，8 路 12 位原始值 |
| Q2 弧线 | 里程+航向排程，灰度最多修正 ±40° | **灰度循迹为主**：灰度误差积分成航向偏置（±55°） |
| Q2 直线 | MPU 航向保持 | 第一段：**灰度循迹直线**（`SEG_LINE`）；第二段：**纯 MPU 保持 180°**（`SEG_STRAIGHT`） |
| 丢线处理 | 航向偏置 ±25° | 记住丢线侧，把航向偏置打到 ±40° 追线 |
| 链路故障 | — | 300 ms 没有帧就判离线：弧线自动退回旧排程、直线退回 MPU |
| 新增日志 | — | `gl=` 在线、`gf=`/`gx=` 有效/坏帧数、`lm=` 当前段是否灰度、`lt=` 灰度航向偏置、`lr=` 灰度转速指令、`a=` 8 路原始值 |
| 死机兜底 | 中断里死循环、主循环可无限等待 | **2 s 看门狗 + 限时等待 + 故障打印**（`RST flags` / `FAULT`），见第 9 节 |
| 弧线→直行 | 里程一到就切 | **先停车、原地转到 180°，再开始直行**（`ARC_SETTLE_*`），见 5.5 |
| 中断优先级 | USART1 低于 TIM1，灰度帧被 I2C 长中断挤掉 | USART1 可打断 TIM1，不再丢帧 |
| 栈 | 1 KB | 2 KB |

`Q3/Q4` 的转向与排程弧线（`SEG_TURN` / `SEG_ARC`）保持原样，只把
`SEG_ARC` 的灰度微调增益改名为 `ARC_GRAY_TRIM_KP/KD`（数值仍是 20 / 4）。

## 1. 打开与编译

1. 安装 Keil MDK5 和 `Keil.STM32F1xx_DFP` 器件包（STM32F103C8）。
2. 双击 `Project.uvprojx` 打开工程。
3. 在 Options for Target → Device 中确认器件为 `STM32F103C8`。
4. 编译：`Project → Build Target`（F7）。
5. 下载：ST-Link 接 `SWDIO / SWCLK / GND / 3.3V`，`Flash → Download`（F8）。
6. 串口：PA9→CH340 RX，GND 共地，115200 8N1。

工程使用 ARMCC V5（`uAC6=0`）。源码为 C90 风格，不依赖编译器扩展。

本版实测编译（Keil MDK 5.36 + DFP 2.4.1 + ARMCC V5.06u6）：
**0 Error / 0 Warning**，Code 20,386 B、RO 2,190 B、RW 264 B、ZI 2,968 B，
Flash 约 22.8 KB、RAM 约 3.2 KB（含 2 KB 栈），在 MDK-Lite 32 KB 限制内。

本版还用主机仿真（把 `App/path.c` 原样编到 PC 上，配一个差速小车 +
8 路传感器模型）跑过整条 Q2 赛道：从正中出发、偏 10/20/30 mm 出发、
偏 3° 出发、以及中途灰度链路断 2 s 都能跑完两段直线 + 两个 180° 弧，
全程横向偏差 ≤ 13 mm，两段弧实测半径 396~405 mm。
**仿真不能代替实车**，见第 8 节试跑顺序。仿真工程在交付包
`_仿真_主机验证\` 里，改增益（例如 `ARC_LINE_KP`）后可以先生成器上验证，
不必每次都上车试。

## 3. 接线（本版有变化，务必先看）

### 3.1 灰度模块：改成串口

灰度模块（CH32V006，型号 CTL_M_TRACK_CH32V006）板上有 `TX / RX` 排针，
固件出厂就是 **115200 8N1、二进制"超级简化协议"**。

| 灰度模块 | STM32 | 说明 |
|---|---|---|
| `+5V` | 5V | 模块 5V 供电，必须共地 |
| `GND` | GND | 共地 |
| `TX` | **PA10**（USART1_RX） | 模块发 → 单片机收 |
| `RX` | **PA9**（USART1_TX） | 单片机发 → 模块收，和 CH340 的 RX **共线** |
| `SCL` / `SDA` | 不接 | 串口模式不用 I2C |
| `OUT-1` ~ `OUT-8` | **全部拔掉** | 本版不再读并行输出 |

**CH340 这边**：只保留 `PA9 → CH340 RX`（看日志），
**CH340 的 TX 不要再接到 PA10**。PA10 现在只接模块 TX，
两个发送端接在一起会打架。

为什么 PA9 可以一拖二：模块上电后只需要收 4 个字节
（`A5 03 15 02`，打开上传模式），之后全部是模块往单片机发。
调试日志是 ASCII（0x20~0x7E），不可能被模块当成 `0xA5` 帧头。

### 3.2 被释放的 8 个引脚

`PA8 / PA11 / PA12 / PA15 / PB3 / PB4 / PB5 / PB14` 原来接 OUT1~8，
本版把它们配成下拉输入（悬空不飘）。**排线要拔掉**：模块的 OUT 高电平
约 4 V，比 3.3 V 电源高，非 FT 引脚长期灌电流会伤 IO。

其余接线（电机、编码器、MPU6050、OLED、按键、电池 ADC）与本版无关，不变。

### 3.3 上电自检（一定要看）

打开串口助手（115200 8N1），上电后应看到：

```
BOOT 16th team STM32F103 Q2-GRAY-UART r8
RST flags=3 POR PIN                  ← 本次复位的原因（详见第 9 节）
GRAY uart 115200, push mode 0x02 (5B + 8 x 12 bit)
IMU calibration, keep the car still...
MPU6050 WHO_AM_I=104 PWR_MGMT_1=0 (ok, expect ID 104)
gyro bias=... range=... (ok)
IMU calibration done
GRAY push-mode cmd A5 03 15 02      ← 紧跟 4 个二进制字节，是发给模块的命令
GRAY link ok, g=24                  ← 收到帧了，g 是当前 8 位黑白位图
t=... run=0 ... g=24 gl=1 gf=.. gx=0 ... a=180,150,210,3550,120,....
```

- `RST flags` 里出现 `IWDG` = 上一次是程序卡住被看门狗救回来的（第 9 节）。
- 没有 `GRAY link ok` / `gl=0`：模块没通。查 5V、GND、TX→PA10、RX→PA9、
  波特率 115200、是不是把 OUT 线当成串口了。
- `a=` 是 8 路原始值：**白底应是几百**（100~600），**黑线上是几千**
  （2500~4000）。哪一路一直很高就是那一路传感器脏了/坏了。

## 4. 控制流程

- TIM1 更新中断：200 Hz（5 ms）。
- 中断内：读灰度串口帧（`Gray_Task`）→ 读 TIM3/TIM4 编码器 →
  读 MPU6050 陀螺仪 Z → 积分航向 → 路径状态机 → 双轮速度 PI → PWM。
- 主循环：按键扫描（20 ms）、OLED（5 Hz）、调试串口（10 Hz）、
  灰度链路看门狗（`Gray_Poll`）。
- 路径：Q1 直线；**Q2 直线-右弧-直线-右弧（全程灰度循迹，两个弧都是向右
  180°，和跑道形赛道一致）**；Q3 左转 38.66°-
  对角线-右转 38.66°-右弧-右转 38.66°-对角线-左转 38.66°-左弧；Q4 重复 Q3 四次。

## 5. Q2 串口灰度循迹（本版核心）

### 5.1 数据链路

```
模块每 10 ms 主动上传一帧：  5B g1L g1H g2L g2H ... g8L g8H   （17 字节）
                 ↓  USART1 RX 中断 → 256 字节环形缓冲
        Gray_Task() 每 5 ms 取空缓冲、拼帧、范围校验（高字节必须 ≤0x0F）
                 ↓
        g = 8 位位图（某路 > 2000 记 1，即"黑"），a= 原始值
                 ↓
        line_error() → e（−1~+1，线在 OUT8 一侧为正）
```

- 帧头 `5B` 让链路能自同步：丢一个字节只丢一帧，不会一直错下去。
- 300 ms 收不到有效帧 → `gl=0`（离线）；`Gray_Poll()` 每 200 ms 重发
  `A5 03 15 02`，模块只要还活着就会恢复上传。
- 在线判定在控制中断里做，路径状态机同一拍就能用上最新 `g`。

### 5.2 转向控制结构

```
w_line  = -(ARC_LINE_KP * e + ARC_LINE_KD * d(e)/dt)     deg/s，限幅 ±ARC_LINE_W_MAX
theta  += w_line * dt，限幅 ±ARC_LINE_THETA_MAX          °，灰度航向偏置（积分项）
yaw_ref = yaw_tangent + theta                            yaw_tangent：直线恒定，弧线按里程转 180°
rate_ref = rate_ff + w_line
turn_corr = ARC_YAW_KP*(yaw_ref - yaw) - ARC_YAW_KD*(gyro_z - rate_ref)
turn      = turn_ff + turn_corr                          弧线才有 turn_ff，直线为 0
左右轮    = base -/+ turn
```

要点：

- **灰度不再只是"微调"**：`theta` 是灰度误差的积分，能到 ±55°，
  车被拉回线后 `theta` 会退回去。直线段 `yaw_tangent` 固定、`turn_ff=0`，
  弧线段 `yaw_tangent` 按里程推进 180°，`turn_ff` 给 400 mm 半径的固定差速。
- 这样弧线的"转弯节奏"由几何前馈保证（不会越跑越偏），"转多少"由灰度决定
  （偏了就多转/少转），两者不抢控制权。
- 弧线结束仍以**里程**为基础。里程到了之后，如果航向还没到 180°，车会
  **先停稳、原地把剩下的角度转到 180°**，然后才开始下一段直行，见 5.5。
- 结束时航向差 ≤3° 直接校正，3~20° 交给下一段去修。
- 丢线（`g=0` 全白）：记住最后看到线的一侧，把 `theta` 打到 ∓40° 往那边追，
  直到重新看到线；`g=255`（全黑/路口）没有方向信息，保持当前偏置。
- 链路掉线（`gl=0`）：弧线自动退回 release1.9 的"排程 + 灰度微调"（`lm=0`），
  直线退回 MPU 航向保持，至少能跑完，不会瞎冲。

### 5.3 参数（都在 `App/app_config.h`）

| 参数 | 默认 | 作用 |
|---|---|---|
| `ARC_LINE_KP` | 60 | 灰度误差 → 航向偏置的积分速度（deg/s per 误差单位） |
| `ARC_LINE_KD` | 20 | 误差变化率的阻尼（deg/s per (误差/s)） |
| `ARC_LINE_D_FILT` | 0.20 | 微分低通，抑制 8 级量化跳变 |
| `ARC_LINE_W_MAX` | 110 | 灰度转速指令限幅（deg/s） |
| `ARC_LINE_THETA_MAX` | 55 | 灰度航向偏置限幅（°），决定"能拉回多远" |
| `ARC_LINE_REACQ_DEG` | 40 | 丢线时的追线偏置（°） |
| `ARC_SETTLE_TOL` | 1 | 交接时航向差超过这个值（°）就触发"停车原地转"，见 5.5 |
| `ARC_SETTLE_DONE_TOL` | 1 | 原地转到位判定（°） |
| `ARC_SETTLE_BRAKE_MS` | 150 | 原地转之前先停稳多久（ms） |
| `ARC_SETTLE_ABS_YAW` | 1 | 180° 从哪算：1=这次跑的起始航向，0=本段弧入口航向（见 5.5） |
| `ARC_YAW_DONE_DEG` | 179 | 防跑飞保护：转过头 179° 且里程 >97% 就结束 |
| `ARC_FF_TRIM` | 1.00 | 弧线曲率前馈微调（见 6.7） |
| `ARC_YAW_KP / KD` | 10 / 0.8 | 内环航向环（沿用旧值） |
| `GRAY_BLACK_ADC` | 2000 | 原始值高于它算"黑"，和模块自身阈值一致 |
| `GRAY_LINK_TIMEOUT_MS` | 300 | 多久没帧算掉线 |
| `GRAY_MASK` | 0x00 | 屏蔽坏通道（默认不屏蔽，见 6.4） |

**调参口诀（看 `e=` 和 `lt=`）**：

- 弧线整体往外抛 / 切内道 → 加大 `ARC_LINE_KP`；
- 车画龙、左右抖 → 先减 `ARC_LINE_KP`，再减 `ARC_LINE_KD`；
- 一偏就满舵、动作很冲 → 减 `ARC_LINE_W_MAX`；
- 入弧时线已经在阵列外、拉不回来 → 加大 `ARC_LINE_THETA_MAX`；
- 弧线半径不对（`Rr=` 不是 400 左右）→ 调 `ARC_FF_TRIM`，见 6.7。

### 5.4 想换某一段的走法

`App/path.c` 的 `g_path_q2[]` 现在是：

```c
{ SEG_LINE,     TRACK_AB_MM, 1.00f, 0, 1 },   /* A->B 灰度跟线（无线时 MPU 直行） */
{ SEG_ARC_LINE, TRACK_ARC_MM, 0.75f, -1, 1 }, /* B->C 灰度弧线 + 180° 交接 */
{ SEG_STRAIGHT, TRACK_CD_MM, 1.00f, 0, 1 },   /* C->D 纯 MPU 保持 180° */
{ SEG_ARC_LINE, TRACK_ARC_MM, 0.75f, -1, 1 }, /* D->A 灰度弧线 */
```

- 第一段改成 `SEG_STRAIGHT`：从起跑就纯 MPU 直行，不再去找线。
- 第三段改成 `SEG_LINE`：第二段也灰度跟线（有胶带时更贴线，丢线自动退回 MPU）。
- 任意 `SEG_ARC_LINE` 改成 `SEG_ARC`：恢复 release1.9 的"里程排程弧线"。
- 类型都在 `App/path.h` 的 `SegType` 里。

### 5.5 弧线 → 直行的"180° 交接"（r8 第二版）

灰度跟线是按"线"走的，它可能比模型算的 400 mm 弧**早一点**走完 1256 mm
（切内道），也可能走外道。里程一到就切直行的话，第二段直行就是歪的。

所以 r8 在弧线结束时加了一步"180° 交接"：

```
弧线里程到（弧长 + 5 mm）
  ├─ 航向差 ≤ ARC_SETTLE_TOL（1°）？ → 是：直接结束弧线
  └─ 否：先停车 ARC_SETTLE_BRAKE_MS（150 ms），
         再原地转到 |航向差| ≤ ARC_SETTLE_DONE_TOL（1°），
         然后结束弧线
  ↓
进入第二段直行（SEG_STRAIGHT，纯 MPU 保持 180°）
```

- 目标的 180° 默认是**相对这次跑的起始航向**（`ARC_SETTLE_ABS_YAW = 1`，
  也就是"MPU 的 yaw 与一开始的 yaw 相隔 180°"）。每一段弧再累加 ±180°，
  所以第二段弧结束是 −360°。
- 想改成"相对本段弧入口的航向"（等价于跟胶带平行、能抵消起跑摆放的斜角）：
  把 `ARC_SETTLE_ABS_YAW` 改成 0。
- 原地转用的是工程里原有的转向律（`TURN_KP/TURN_MIN_MMPS/TURN_MAX_MMPS`），
  2.5 s 转不到就放弃并把残差交给直行的航向环（`ARC_YAW_FIX_MAX` 以内）。
- 内轮停住、外轮转，车绕内轮原地转；仿真里 12° 的残差约 0.1 s 转完，横向
  几乎不移动。
- 日志里每段弧的 `why=` 就是结束原因：`1` 航向本来就到位（含防跑飞保护）、
  `2` 丢线提前结束、`3` 里程到、**`4` 停车原地转到 180° 后结束**。

**第二段直行为什么用 `SEG_STRAIGHT`（纯 MPU）**：这样它的方向只由这次要
求的 180° 决定，不看灰度。要注意代价：MPU 只保持航向、不修正横向位置，
所以弧线出口的横向偏差会一直带到下一个弧入口；如果第二段地面**有胶带**、
希望它自己贴回去，把 `g_path_q2[]` 里的 `SEG_STRAIGHT` 改成 `SEG_LINE`
即可（丢线时它仍会自动用 MPU 保持航向，等于两者的结合）。

## 6. 首次上电必须标定

所有参数集中在 `App/app_config.h`。

### 6.1 电机方向
架空车轮，按 KEY_START 启动 Q1，观察两轮是否同向向前。
- 左轮反转：交换 TB6612 的 AO1/AO2，或把 `MOTOR_LEFT_INVERT` 改为 1。
- 右轮反转：交换 BO1/BO2，或把 `MOTOR_RIGHT_INVERT` 改为 1。

### 6.2 编码器符号
手推车前进，串口 `L=`、`R=` 应为正。若为负：
- 交换该电机 C1/C2，或把 `ENCODER_LEFT_SIGN` / `ENCODER_RIGHT_SIGN` 改为 -1。

### 6.3 轮径/计数当量
`COUNTS_PER_MM` 默认按 MG513（11 线 × 4 × 30 = 1320 count/rev）和 65 mm 轮径：
`1320 / (π×65) = 6.46 count/mm`。
实测方法：车沿直线推 1000 mm，记录串口 `d=` 的变化量 Δ，改成
`COUNTS_PER_MM = Δ / 1000`。

### 6.4 灰度自检（串口版，必做）
把车放在**纯白**地面、探头下什么都不放，看 `a=` 的 8 个数：

- 都应是几百（100~600）；哪一路接近 4095 就是脏了/坏了/焊接不良。
- 黑线压到哪一路，哪一路的数会升到 2500~4000。
- 用黑胶带从左到右慢慢划过探头，看 `g=` 的位是不是从低到高依次翻转，
  确认 **OUT1 在左、OUT8 在右**。如果反了，把 `GRAY_REVERSE` 改为 1。
- 某一路始终为黑又不想马上修：`GRAY_MASK` 屏蔽该位
  （例如第 6 路 → `0x20u`），修好后改回 `0x00u`。

`g=` 的 8 位是"1=黑"的位图，十进制打印，例如 `g=24` = 0b00011000 =
第 4、5 路压线（正常在线上时中间两路为 1）。

### 6.5 陀螺仪零偏
上电后保持静止 2 s，串口打印 `IMU calibration`。若航向漂移大：
- 检查 MPU6050 是否水平、I2C 是否稳定；
- 重新上电校准；
- 若手动左转（逆时针）时串口 `yaw` 反而变小，把 `GYRO_Z_SIGN` 改为 `-1.0f`。

本版弧线以灰度为主，陀螺仪零偏只影响内环阻尼和 `Rr=` 统计，不达标也能跑，
但 `Rr=` 会不准，所以还是校准好。

### 6.6 速度/转向参数
| 参数 | 默认 | 作用 |
|---|---|---|
| `SPEED_KP/KI/KFF` | 1.10 / 18 / 3.27 | 速度环 |
| `YAW_KP/KD` | 8.0 / 1.5 | 直线航向（仅 Q1/Q3/Q4 直线和掉线回退） |
| `TURN_KP` | 5.0 | 38.66° 转向 |
| `SPEED_SET` | 600 mm/s | 按键可调 300~900 |
| 弧线段 `speed_ratio` | 0.75 | 弧线速度 = 基础速度 × 0.75 |

第一次试跑把速度降到 **300~450**（KEY_SPEED 按到最低几档），跑顺了再提。

### 6.7 `ARC_FF_TRIM` 怎么标

弧线的固定差速是按半径 400 mm 算的。实测半径偏大（车往线外飘）就把
`ARC_FF_TRIM` 调大：

1. 跑一次 Q2，看串口每段弧结束打印的 `Rr=`（实测半径）；
2. `ARC_FF_TRIM = Rr / 400`：`Rr=440` → 1.10，`Rr=360` → 0.90；
3. 灰度跟线本身能盖住 10~20% 的曲率误差，`Rr` 在 380~420 不调也行。

## 7. 串口输出

```
t=12345 run=1 mode=2 seg=2 d=1234 yaw=-92 gz=-61 g=24 gl=1 gf=812 gx=0 e=-14 yr=-95 gc=-3 lt=-3 lr=-12 lm=1 Rr=398 L=430 R=470 bat=12.1V a=180,150,210,3550,120,160,140,150
```

| 字段 | 含义 |
|---|---|
| `t` | 5 ms 计数×5，单位 ms |
| `run` | 0 停止 / 1 运行 |
| `mode` | 1~4 对应 Q1~Q4 |
| `seg` | 当前片段序号 |
| `d` | 累计里程 mm |
| `yaw` | 航向角（°） |
| `gz` | 陀螺仪 Z 角速度（0.1 °/s） |
| `g` | 8 位灰度位图（十进制，bit0=OUT1，1=黑） |
| `gl` | **灰度串口链路：1=在线，0=掉线** |
| `gf` | **收到的有效灰度帧数**（每秒应涨 100 左右） |
| `gx` | **被丢弃的坏帧数**，一直涨说明串口线/电平有问题 |
| `e` | 归一化灰度误差 ×100（−100~+100，线在 OUT8 一侧为正） |
| `yr` | 航向参考（°）：直线={段起点+灰度偏置}，弧线={切线+灰度偏置} |
| `gc` | 灰度给出的航向偏置（°），**和 `lt` 同一个数** |
| `lt` | **灰度航向偏置（°）**，本版主要观察量 |
| `lr` | **灰度转速指令（°/s）**，看它有没有在动 |
| `lm` | **当前段是否灰度闭环**：1=是，0=掉线回退 |
| `Rr` | 实测弧线半径（mm） |
| `L`/`R` | 左右轮速 mm/s |
| `bat` | 电池电压 |
| `a` | **8 路灰度原始值**，白底几百、黑线几千 |

每段弧线结束会额外打印一行汇总：

```
ARC d=1254 yaw=-179 Rr=401 lm=1 why=1 e=-14..14 gc=-5..3 g=24..56 lost=0
```

- `lm`：这段弧是不是灰度在控制（1=是）
- `why`：结束原因，`1`=航向本来就到位（正常）、`2`=丢线提前结束、`3`=里程到、
  **`4`=停车原地转到 180° 后结束**
- `d`：这段弧的总里程；`why=4` 时含原地转之前滑行的那几十毫米
- `e`：灰度误差的最小/最大值，说明线在阵列里左右跑动过
- `gc`：灰度航向偏置的最小/最大值，`0..0` 说明灰度一次都没参与
- `g`：原始位图最小/最大值，`g=0` 出现说明丢过线
- `lost`：丢线采样数

**判断灰度有没有在干活**：跑 Q2 时看 `lm=1`、`e` 在小范围变化、
`lt` 不是一直贴着 ±55、`lost` 很小。若 `e` 一直是固定值且 `g` 不变 →
模块没通或者线不在阵列下。

## 8. 试跑顺序

1. 架空空转：KEY_MODE 选 Q2，KEY_START 启动，看 `L/R`、`gl=1`、`a=`。
2. 白底静置：`g` 应为 0（没有线），`a=` 都应是几百。
3. 手推车沿赛道走一遍：`g` 应随线位变化、`e` 正负跟着线左右走，
   并且**线在右边时 `e` 为正**。反了改 `GRAY_REVERSE`。
4. 低速（300~450）跑 Q2：先看能不能贴住线跑完两个弧，再看 `Rr=`。
5. 逐步提速到 600，按 5.3 节微调。

## 9. 卡顿 / 无响应怎么查（r8 新增诊断）

程序"卡住"有三种完全不同的原因，r8 让它们各自留下证据，先看现象再动手：

| 现象 | 含义 | 依据 |
|---|---|---|
| 串口一直不出新行，车还在跑 | 主循环死了，中断还活着 | 2 s 后看门狗复位，重启后打印 `RST flags=.. IWDG` + `WARNING: previous run was reset by the watchdog` |
| 串口打印 `FAULT HARD stage=..` | 硬件异常（堆栈/总线/野指针） | `stage=` 指出最后执行到哪：1 启动 2 初始化 3 界面 4 调试输出 5 灰度轮询 6 控制中断(编码器+灰度) 7 MPU6050 读 8 路径状态机 9 电机输出；接着板载 LED 快闪（HARD 3 下、MEM 4 下、BUS 5 下、USAGE 6 下），2 s 后看门狗复位 |
| 串口反复打印 `BOOT ...` | 在复位循环：供电跌落/接触不良/看门狗 | 看 `RST flags`：只有 `POR PIN` = 电源或复位脚；带 `IWDG` = 程序卡住被救回；`SW` = 调试器复位 |
| 串口正常、只是 `gl=0` / `g` 不动 | 灰度链路断了，不是死机 | 弧线会自动退回旧排程（`lm=0`），车仍会跑完 |

r8 同时做了三件"兜底"的事：

1. **看门狗（2 s）**：主循环每圈喂狗；卡住就自动复位，不会让车带着故障一直跑。
   Keil 调试时看门狗会被调试器冻结（`DBG_IWDG_STOP`），停在断点上不会复位。
   想彻底关掉：`app_config.h` 的 `IWDG_TIMEOUT_MS` 改成 0。
2. **所有等待都有上限**：串口 `TXE`、ADC `EOC` 这两个 `while` 以前可以无限等
   （供电瞬间跌落就会卡死在里面），现在超时就放弃、主循环继续跑。
3. **中断优先级调整**：MPU6050 是软件 I2C，在 5 ms 控制中断里要花约 1.5 ms；
   以前 USART1 接收中断排在它后面，灰度帧在硬件里被覆盖丢掉（`gx=` 会持续增长）。
   现在 USART1 可以打断控制中断，只花几微秒把字节放进环形缓冲，帧不再丢。

**如果还是"一插 USB 调试就卡"，优先查两处硬件**（这两条都是本版新接线引入的）：

1. **CH340 的 TX 是否还接在 PA10 上**。PA10 现在只接灰度模块的 TX；
   CH340 的 TX 还接的话，两个推挽输出版本会对着干，模块会被灌电流、供电也会抖。
   USB 一插上 CH340 就上电，正好符合"一调试就出事"。
2. **调试时车是不是由 USB/ST-Link 供电**。灰度模块 8 路红外 LED 大约要
   100~250 mA，USB 5V（尤其是 ST-Link 的 3.3V）带不动，5V/3.3V 一跌就会
   复位或死机。调试时也让车用电池供电，USB 只接 TX/RX/GND。

一个可复现的判据：把 CH340 的 TX 拔掉、车用电池供电，如果连续多次上电都不再卡，
那问题就在这两条上，而不是固件。

## 10. 常见问题

| 现象 | 检查 |
|---|---|
| 开串口没有 `GRAY link ok`，`gl=0` | 5V/GND、模块 TX→PA10、模块 RX←PA9、CH340 的 TX 有没有拆掉、波特率 |
| `a=` 全 0 或全 4095 | 模块没供 5V / 探头没对地 / 传感器坏 |
| `a=` 某一路总是很高 | 那一路脏了/坏了：擦镜头，或用 `GRAY_MASK` 屏蔽 |
| `e` 有值但车往反方向修 | `GRAY_REVERSE` 改 1（OUT1/OUT8 左右反了） |
| 弧线切内道/外抛 | 加大 `ARC_LINE_KP`；再不行按 6.7 调 `ARC_FF_TRIM` |
| 弧线画龙 | 减 `ARC_LINE_KP`（60→40），再减 `ARC_LINE_KD`（20→12） |
| 入弧就被甩出阵列，越跑越远 | 加大 `ARC_LINE_THETA_MAX`（55→70），并确认直线段 `e` 本来就接近 0 |
| 跑着跑着 `lm` 在 0/1 之间跳 | 串口线接触不良，或模块供电不稳导致反复复位 |
| Keil 编译报 `DWT`/`CoreDebug` 未定义 | 已改为地址访问，确认 `System/Delay.c` 是最新版本 |
| 下载后无反应 | BOOT0=0，SWD 接线，按复位；串口是否有 `BOOT` 字样 |
| OLED 不亮 | PB8/PB9 是否接反，3.3 V，地址 0x3C |
| MPU6050 读不到 | PB10/PB11 是否接反，AD0 接地，地址 0x68 |
| 电机不转 | STBY 是否 3.3 V，VM 是否有 12 V，PWMA/PWMB 是否有波形 |
| 编码器计数不变 | 编码器 VCC/GND，C1/C2 是否接对，TIM3/TIM4 是否使能 |

## 11. 已知假设（装车前确认）

1. 电机为 WHEELTEC MG513，11 线编码器，减速比 30，12 V。
2. 轮径 65 mm；轮距 150 mm；如实测不同，改 `app_config.h`。
3. 编码器 VCC 接 3.3 V；若该批次必须 5 V，C1/C2 需加 1 kΩ 串联和 3.3 V 钳位。
4. 灰度模块固件是"超级简化协议"（协议版本 0x07，设备 ID 0x42），
   UART 115200 8N1，寄存器 0x15 = 2 时按 `5B + 16 字节` 主动上传。
   如果模块被刷成别的固件，本节命令要跟着改（见 `Bsp/gray_uart.c` 顶部）。
5. 灰度模块 UART 是 3.3 V 电平（板载 3.3 V LDO 给 CH32V006 供电），
   直连 STM32 的 FT 引脚没问题；**但 OUT 并口不要再用**。
6. TB6612 模块丝印以实物为准；VM=12 V，VCC=3.3 V，STBY=3.3 V。
7. 蜂鸣器为 5 V 有源，经 S8050 驱动；无源蜂鸣器需改代码输出 2 kHz PWM。
